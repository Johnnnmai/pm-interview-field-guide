# Product Management Jobs Analysis

Generated from 895 job descriptions extracted from builtin.com.

I searched for jobs containing "Product Manager" keyword from LA, NY, London, Amsterdam and Berlin for last 4 weeks. I did it at the beginning of February 2026, so it mostly contains jobs published in January 2026.

All numbers here come from quantitative analysis in the [analysis notebook](../job-market/analysis.ipynb).

Summary

- 70% of roles work directly on product (roadmap, discovery, delivery)
- 93% need skills beyond just product sense - it's a cross-functional role
- 35.9% of roles mention user research - the most common skill across all jobs
- 64.3% of PM roles require some technical literacy
- Enterprise SaaS (359 jobs) > Consumer (214 jobs) > Platform (205 jobs)


## "Product Management" Job Types

Job positions we analyzed fall into these categories:

- Product-First
- Product-Support
- Technical PM

### Product-First: 621 jobs (69.4%)

Working ON product strategy and execution directly.

What they own:

- Roadmap definition and prioritization
- User research and discovery
- Feature specs, PRDs, and acceptance criteria
- Metrics definition and success measurement
- A/B testing and experimentation frameworks

Example responsibilities:

- "Own product roadmap for the consumer experience"
- "Drive discovery sprints to validate new opportunities"
- "Define success metrics and run A/B experiments"
- "Ship features from concept to launch"
- "Prioritize backlog using RICE framework and customer data"

Position title examples

- Product Manager
- Senior Product Manager
- Group Product Manager
- Lead Product Manager
- Staff Product Manager
- Principal Product Manager
- Director of Product


### Product-Support: 255 jobs (28.5%)

Working NEAR product but NOT ON product strategy itself.

These roles enable product work by building the platforms, analytics infrastructure, and tools that Product-First PMs use.

What they own:

- Analytics platforms and internal dashboards
- Data pipelines for experimentation
- Internal tooling and workflow automation
- Product operations and process design
- Deployment and release coordination

Example responsibilities:

- "Build analytics platform for product teams"
- "Pipeline data for experimentation infrastructure"
- "Build internal tooling for product operations"
- "Build dashboards and reporting systems"
- "Create internal tools for product experimentation"

Position title examples

- Product Operations Manager
- Analytics Product Manager
- Platform Product Manager
- Technical Product Manager (infrastructure focus)
- Product Manager - Internal Tools
- Product Manager - Data Platform


### Technical PM: 16 jobs (1.8%)

Deep technical ownership without traditional PM scope.

What they own:

- System architecture decisions
- API design and platform contracts
- Developer experience and SDK strategy
- Technical debt management
- Infrastructure reliability

Position title examples

- Technical Product Manager - Infrastructure
- Product Manager - Developer Platform
- Technical Product Manager - API
- Product Manager - ML Platform

These "Product Manager" roles are traditional engineering lead roles rebranded with the PM title. They do deep technical work (architecture, API design, infrastructure) without core product management components.


### How to Tell the Difference

The key question is: Does this role own product strategy, or enable it?

Product-First:

- Owns roadmap and prioritization
- Runs user research
- Defines success metrics
- Ships customer-facing features
- Drives go-to-market

Product-Support:

- Builds platforms for other PMs
- Manages analytics infrastructure
- Builds experimentation tooling
- Creates internal dashboards
- Builds ops workflows for product teams

Technical PM:

- Owns system architecture
- Works with engineering infrastructure
- Builds developer-facing platforms
- Does NOT own customer-facing roadmap

### Technical PM Use Cases

- API strategy - Platform products that require deep API understanding
- Data products - Analytics and ML-powered products requiring data fluency
- Developer tools - SDKs, CLIs, developer experience products
- Infrastructure products - Cloud, networking, reliability products
- Performance - Latency-sensitive products, optimization-focused roles
- Security - Security products, compliance-driven development
- Regulated industries - Healthcare, finance, requiring regulatory knowledge

Key findings:

1. Most PMs don't need deep technical skills - Only ~20% have any deep technical expectation
2. Primary technical roles are rare - Only 4% focus on technical depth as main responsibility
3. Most common technical PM use case - API and platform products, data products
4. Deep technical PM is a specialization - Not a core PM skill, more advanced

Bottom Line

- Deep technical skills are optional for most PMs.
- Focus on product sense and metrics first.
- Learn deep technical skills if targeting platform PM roles, developer tool products, or data/ML-focused product areas.


## Metrics and Experimentation Skills

39.6% of Product-First roles explicitly require metrics and experimentation skills (A/B testing, metrics trees, funnel analysis, retention tracking, experimentation design). Metrics definition appears in 69 jobs (11.1%) as an explicit skill, but the real demand is broader - it shows up across responsibilities, not just skill lists.

This is the emerging differentiator. User research and roadmapping are becoming baseline expectations. The ability to measure whether a product actually works - A/B tests, metrics trees, retention cohorts, funnel optimization - is what separates candidates.


## Key Insight: Discovery + Delivery = 70%+ of Product Scenarios

The two dominant disciplines are:

- Discovery - understand what customers need (user research, data analysis, competitive analysis)
- Delivery - ship solutions and measure impact (roadmap execution, sprint management, metrics tracking)

If you learn these two disciplines deeply, you can handle most product management scenarios.


## Learning Path for Product Managers

- Foundation - SQL, analytics basics, business communication
- Product Basics - PRD writing, user research, prioritization frameworks (RICE, ICE)
- Metrics - A/B testing, metrics trees, funnel analysis, retention cohorts
- Tools - Amplitude/Mixpanel, Jira/Linear, Figma basics
- Strategy - Competitive analysis, market sizing, go-to-market
- Execution - Agile/Scrum, stakeholder management, launch coordination

For a structured learning path with real PM interview questions, product strategy frameworks, and salary data from 500+ offers, see the [100x Product Manager](https://gumroad.com/l/100x-pm) field guide.

The typical product management stack:

- STRATEGY layer - Market analysis, competitive intelligence, vision
- DISCOVERY layer - User research, customer interviews, data analysis
- PRIORITIZATION layer - RICE, ICE, opportunity scoring, metrics trees
- EXECUTION layer - Sprint planning, PRDs, acceptance criteria
- MEASUREMENT layer - A/B testing, funnel analysis, retention, NPS
